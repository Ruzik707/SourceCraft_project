# Демонстрационный стенд

Как получить публичный URL, по которому жюри откроет работающий сервис.

## Что потребуется

Виртуальная машина с Docker. Ресурсы небольшие: при сборке витрины из 27 761
репозитория пик потребления — **418 МБ**, в покое сервис занимает меньше.

| Параметр | Рекомендация | Минимум |
| --- | --- | --- |
| vCPU | 2 | 1 |
| RAM | 4 ГБ | 2 ГБ |
| Диск | 20 ГБ | 10 ГБ (выгрузка занимает 58 МБ) |
| ОС | Ubuntu 22.04 | любая с Docker |

В Yandex Cloud подходит самая дешёвая конфигурация Compute Cloud с прерываемой ВМ.

## Шаг 1. Машина и Docker

Создайте ВМ с публичным IP, разрешите входящий трафик на порт 80 (и 443, если будет
домен). Дальше по SSH:

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker
```

## Шаг 2. Код и данные

```bash
git clone ssh://ssh.sourcecraft.dev/lct-hackaton-2026/case-18-repo-health-score-team-31.git
cd case-18-repo-health-score-team-31
```

Выгрузка сборщика `repo_health_report.csv` должна лежать в корне проекта — без неё
сервис поднимется, но рейтинг будет пустым. Если файла нет в репозитории, скопируйте его
с машины, где работал сборщик:

```bash
scp repo_health_report.csv user@<IP>:~/case-18-repo-health-score-team-31/
```

## Шаг 3. Настройки стенда

```bash
cp .env.example .env
```

Заполните в `.env`:

```bash
# Адрес стенда: и интерфейс, и API отдаются с одного адреса
PUBLIC_API_URL=http://<IP-или-домен>
FRONTEND_URL=http://<IP-или-домен>
STAND_PORT=80

# Свой ключ подписи сессий — не оставляйте значение из примера
SECRET_KEY=<случайная строка, например из `openssl rand -hex 32`>

# Демо-вход: позволяет жюри пройти сценарий кабинета без своего аккаунта SourceCraft
ALLOW_DEMO_AUTH=true

# ВАЖНО: на публичном стенде запасной токен платформы оставьте пустым,
# иначе каждый вошедший увидит репозитории его владельца
SOURCECRAFT_TOKEN=
```

Про демо-вход. Он даёт сессию без Яндекса по ссылке `/api/v1/auth/yandex/login?demo=1`.
Риск ограничен: демо-пользователь не имеет токена платформы и видит только публичные
данные из снимка. Если стенд должен быть строгим, поставьте `ALLOW_DEMO_AUTH=false` —
тогда кабинет доступен только после настоящего входа через Я ID.

## Шаг 4. Запуск

```bash
docker compose up -d --build
docker compose logs -f backend      # дождаться «Витрина готова»
```

Первый старт занимает около минуты: сборка образов плюс чтение выгрузки.

Откройте `http://<IP>` — должен открыться рейтинг.

## Шаг 5. Вход через Я ID на стенде

В приложении на oauth.yandex.ru добавьте в список Redirect URI адрес стенда:

```
http://<IP-или-домен>/auth/callback
```

Адрес должен совпадать точно, включая протокол и порт. Пока он не добавлен, вход будет
возвращать ошибку от Яндекса, а остальной сервис продолжит работать.

Если Яндекс не принимает адрес без HTTPS, поднимите домен с сертификатом — см. ниже.

## HTTPS и домен

Самый быстрый путь — бесплатное имя вида `<IP>.sslip.io`, которое резолвится в ваш IP без
регистрации домена, плюс Caddy с автоматическим сертификатом Let's Encrypt. Добавьте в
`docker-compose.yml`:

```yaml
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    ports: ["80:80", "443:443"]
    command: caddy reverse-proxy --from <IP>.sslip.io --to web:80
    volumes:
      - caddy-data:/data
```

и уберите проброс порта у сервиса `web`. В `.env` пропишите
`PUBLIC_API_URL=https://<IP>.sslip.io` и тот же адрес в `FRONTEND_URL`, а в приложении
Яндекса — `https://<IP>.sslip.io/auth/callback`.

## Обновление данных на стенде

Сборщик в образ не входит: он тяжёлый и долгий, ему нужен доступ к платформе. Варианты:

**Собирать на отдельной машине**, а на стенд копировать готовую выгрузку:

```bash
scp repo_health_report.csv user@<IP>:~/case-18-repo-health-score-team-31/
curl -X POST http://<IP>/api/v1/admin/rebuild
```

**Собирать на самой ВМ** — поставьте `uv` и запускайте сборщик из `collector/` по
инструкции в его README, файл обновляется на месте. Тогда пропишите в `.env` бэкенда
`COLLECTOR_COMMAND`, и анализ из кабинета будет собирать данные по-настоящему.

Планировщик внутри сервиса в любом случае пересчитывает витрину по расписанию из
`REPO_HEALTH_SCHEDULE` и пишет историю оценок.

## Проверка перед показом

```bash
curl -s http://<IP>/api/v1/stats | head -c 200
curl -s "http://<IP>/api/v1/repos?page_size=1" | head -c 200
curl -s http://<IP>/api/v1/repos/userver/userver | head -c 200
```

И глазами в браузере:

- [ ] рейтинг открывается, фильтры и сортировки работают;
- [ ] страница анализа показывает оценку, категории, рекомендации;
- [ ] выгрузка отчёта в Markdown скачивается, печать в PDF открывается;
- [ ] вход через Я ID проходит и возвращает в кабинет;
- [ ] запуск анализа отрабатывает и показывает стадии;
- [ ] страница методики открывается.

## Если стенд не нужен постоянно

Для короткой демонстрации хватит туннеля с рабочей машины — стенд поднимать не нужно:

```bash
docker compose up -d --build
ssh -R 80:localhost:8080 nokey@localhost.run     # выдаст публичный https-адрес
```

Адрес меняется при каждом запуске, поэтому его придётся каждый раз добавлять в Redirect
URI приложения Яндекса. Для записи видео и быстрой проверки подходит, как постоянный
стенд — нет.

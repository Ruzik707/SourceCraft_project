# Внешние сервисы и использование ИИ

Документ отвечает на требование раздела 9.5 ТЗ: какие внешние сервисы задействованы в
решении и как применялся искусственный интеллект.

## Внешние сервисы

Сервис обращается только к ресурсам SourceCraft и Яндекс ID. Других внешних вызовов в
рабочем контуре нет.

| Сервис | Адрес | Зачем | Что передаётся |
| --- | --- | --- | --- |
| API платформы SourceCraft | `api.sourcecraft.tech` | метаданные репозиториев, issues, merge request, релизы, рейтинг, организации и репозитории пользователя | личный токен доступа или токен Я ID |
| AppSec SourceCraft | `appsec.sourcecraft.tech` | результаты SAST, SCA и secret scanning для категории Security | идентификатор репозитория |
| Git SourceCraft | `git.sourcecraft.dev` | поверхностное клонирование для анализа документации, активности и состояния кода | — |
| Яндекс ID | `oauth.yandex.ru`, `login.yandex.ru` | авторизация пользователя и получение профиля | код авторизации, затем токен доступа |

Аналитика, телеметрия, внешние хранилища и облачные API не используются.

## Обращение с данными репозиториев

Исходный код не хранится дольше, чем нужно для анализа: сборщик клонирует репозиторий во
временный каталог, считает метрики и удаляет рабочую копию. В выгрузку попадают только
агрегаты — количество файлов и строк, число пометок TODO и FIXME, даты, счётчики, — но не
содержимое файлов. Фрагменты кода никуда не публикуются и не передаются третьим лицам,
поэтому лицензии анализируемых репозиториев не нарушаются.

Данные закрытых репозиториев обрабатываются только в рамках прав авторизованного
пользователя: такие репозитории исключены из публичного рейтинга, статистики и списка
языков, а отчёт по ним отдаётся только владельцу. Токен платформы хранится в сессии
пользователя и удаляется вместе с ней.

## Использование искусственного интеллекта

Для формирования текстовых сводок и приоритизации рекомендаций сервис использует языковую модель (Llama 3 через провайдера Groq). Интеграция реализована с акцентом на безопасность данных и воспроизводимость результатов:

- **Генерация рекомендаций по кнопке:** Эндпоинт `POST /recommendations/ai` принимает агрегированный список фактов, собранных локальным детерминированным движком (`scoring/recommender.py`), и отправляет их в LLM для перевода в читаемый, приоритизированный формат.
- **Безопасность исходного кода:** Исходный код **не передается** во внешние ИИ-сервисы. LLM получает исключительно итоговые метрики и статистику (например, "В репозитории отсутствует файл LICENSE" или "Доля успешных пайплайнов ниже 80%").
- **Независимость оценки:** Repo Health Score по-прежнему считается строгой математической методикой без участия нейросетей, что гарантирует воспроизводимость оценки. ИИ используется исключительно как ассистент для интерпретации уже найденных проблем.
- **Отказоустойчивость:** Если внешнее API недоступно или не настроен ключ, бэкенд мгновенно переключается на встроенные правила fallback-рекомендаций, не блокируя работу интерфейса.

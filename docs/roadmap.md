# План развития до финальной версии

Что сделано к промежуточной сдаче и что предстоит. Порядок — по убыванию влияния на
оценку решения.

## Готово

- Сбор данных по всему открытому каталогу: **27 761 репозиторий**, шесть категорий
  сигналов, порционный обход с приоритетом самых старых записей.
- Методика Repo Health Score с весами, подобранными на исторической выборке, и
  правилами обработки отсутствующих данных.
- REST API: рейтинг с фильтрами и сортировками, полный отчёт по репозиторию,
  справочники, статистика.
- Веб-интерфейс: рейтинг, страница анализа с раскрытием до фактов, сравнение проектов,
  страница методики, светлая и тёмная темы.
- Авторизация через Я ID, личный кабинет, запуск анализа по требованию со стадиями
  сбора, повторный запуск с разницей оценки.
- Выгрузка отчёта в Markdown и PDF.
- Периодический пересчёт по расписанию с записью истории оценок.
- Защита закрытых репозиториев: вне публичного рейтинга, отчёт только владельцу.

## До финальной версии

### 1. Закрыть требования ТЗ, которые пока не выполнены

| Что | Почему важно | Оценка |
| --- | --- | --- |
| Установить `src` CLI и пересобрать часть репозиториев | ТЗ требует работы и с API, и с CLI платформы; код готов, но бинарь не установлен и `platform_cli=false` во всех записях | полдня |
| Показать Security на репозитории с включённым AppSec | сейчас данные доступны у одного проекта из 27 761, категория почти всегда исключена | зависит от доступа |
| Решить вопрос нейтральных значений в методике | документация и активность получают баллы даже когда рабочую копию получить не удалось | день, зона методики |

### 2. Довести полноту данных

- Прогнать полный обход каталога сборщиком: при четырёх параллельных сборах это около
  пяти суток, поэтому запускать надо заранее и непрерывно.
- Поднять сбор на стенде и включить `COLLECTOR_COMMAND`, чтобы анализ из кабинета
  собирал свежие данные, а не пересчитывал снимок.
- Накопить историю: динамика Score появляется после второго планового пересчёта.

### 3. Функции со звёздочкой

| Направление | Что добавить |
| --- | --- |
| Публичность результата | SVG-бейдж для README (ручка `/badge/{owner}/{name}.svg`), серверная выгрузка PDF |
| Рейтинг и сравнение | динамика позиции в рейтинге, история оценки на графике, объяснение позиции |
| Защита рейтинга | выявление накрутки лайков, пустых коммитов и искусственной активности |
| AI-возможности | сводка для менеджера поверх уже посчитанных фактов, с пометкой, что текст сгенерирован |

Первые два направления опираются на уже готовые данные и стоят недорого. Защита от
накрутки требует отдельного анализа паттернов и в приоритете ниже.

### 4. Инженерное качество

- **Тесты бэкенда и интерфейса.** Сейчас тестами покрыт только сборщик (18 тестов).
  Нужны тесты расчёта витрины, сборки ответов API и правил доступа к закрытым
  репозиториям — это самая уязвимая часть.
- **Постоянный стенд с HTTPS** вместо адреса по IP, чтобы вход через Я ID работал без
  оговорок.
- **Мониторинг**: сейчас о проблемах сбора можно узнать только из логов и блока
  «Полнота данных» в отчёте.

### 5. Продуктовые улучшения

- Подписка на изменения Score своего репозитория.
- Сравнение с похожими проектами: «ваш Score ниже медианы по языку Python».
- Экспорт рейтинга в CSV для командных обзоров.
- Страница организации: здоровье всех проектов одной командой.

## Риски

| Риск | Что делаем |
| --- | --- |
| Платформа не отдаёт AppSec и историю CI без прав | категории помечаются как «нет данных» и не портят оценку; для демонстрации нужен свой репозиторий со сканированием |
| Полный обход каталога занимает дни | обход идёт порциями и непрерывно, приоритет у самых старых записей |
| Один репозиторий может собираться часами | таймаут на репозиторий, очередь не блокируется |
| Методика меняется по ходу | версия методики пишется в каждый отчёт, история оценок хранится с указанием версии |

# SourceCraft Repo Health — веб-интерфейс

Одностраничное приложение на React + TypeScript + Vite: публичный рейтинг здоровья
репозиториев, страница анализа с Repo Health Score и рекомендациями, личный кабинет с
входом через Я ID и выгрузка отчётов в Markdown и PDF.

## Быстрый старт

```bash
cd frontend
npm install
cp .env.example .env     # по умолчанию VITE_DATA_SOURCE=api — нужен поднятый бэкенд
npm run dev              # http://localhost:5173
```

Сборка и просмотр production-версии:

```bash
npm run build            # tsc + vite build -> dist/
npm run preview          # http://localhost:4173
npm run typecheck        # только проверка типов
```

Требуется Node.js 20+ (проверено на 22 и 23).

## Переменные окружения

| Переменная | Значения | Назначение |
| --- | --- | --- |
| `VITE_DATA_SOURCE` | `api` \| `mock` | боевой бэкенд или снимок в `public/mock` |
| `VITE_AUTH_SOURCE` | `api` \| `mock` | то же отдельно для личного кабинета |
| `VITE_API_BASE_URL` | строка | базовый путь API, по умолчанию `/api/v1` |
| `VITE_PROXY_TARGET` | URL | куда Vite проксирует `/api` в режиме разработки |

Переменные читаются на этапе сборки: после изменения нужен перезапуск `npm run dev`.
Чтобы показать интерфейс без поднятого бэкенда:

```bash
VITE_DATA_SOURCE=mock npm run dev
```

## Автономный режим

`VITE_DATA_SOURCE=mock` включает транспорт `src/api/mock.ts`: он отдаёт те же структуры,
что и бэкенд, но читает подготовленный снимок данных из `public/mock`. В этом режиме
работают все сценарии, включая вход через Я ID (эмулируется тем же маршрутом
`/auth/callback`) и запуск анализа с прогрессом по стадиям.

Снимок собирается из сырой выгрузки сборщика:

```bash
python3 tools/build_mock_data.py \
  --csv repo_health_report.csv \
  --out frontend/public/mock \
  --limit 1500          # сколько репозиториев положить в рейтинг
```

Команда запускается из корня репозитория.

Скрипт кладёт `repos.json`, `languages.json`, `stats.json`, `me.json` и по файлу на
репозиторий в `reports/`. Скоринг внутри скрипта — демонстрационный: боевые значения
приходят из витрины команды. Полный набор занимает около 26 МБ; для репозитория с
исходниками разумно уменьшить `--limit`.

## Структура

```
src/
  api/          типы контракта, HTTP-клиент, мок-транспорт, фасад и хуки React Query
  auth/         провайдер авторизации Я ID (токен, профиль, логин/логаут)
  components/
    layout/     каркас страницы, защита приватных маршрутов, error boundary
    ui/         примитивы: карточки, бейджи, выпадающие меню, тосты
    score/      SVG-визуализации: кольцо Score, радар категорий, полоски, спарклайн
    report/     отчёт: карточки категорий, рекомендации, пробелы в данных, выгрузка
  lib/          форматирование, цветовые шкалы, генерация Markdown, тема, история запусков
  pages/        рейтинг, страница анализа, сравнение, методика, кабинет, вход, анализ
  styles/       токены дизайна, общие стили, печатные стили для PDF
public/mock/    снимок данных для демо-режима
```

## Маршруты

| Путь | Назначение |
| --- | --- |
| `/` | рейтинг здоровья открытых репозиториев |
| `/repo/:owner/:name` | страница анализа репозитория |
| `/compare?repos=a/b,c/d` | сравнение до четырёх проектов |
| `/methodology` | методика расчёта Score |
| `/login`, `/auth/callback` | вход через Я ID |
| `/dashboard` | личный кабинет: свои репозитории |
| `/dashboard/analyze/:owner/:name` | запуск анализа, прогресс, результат |

Дополнительно `?theme=dark` или `?theme=light` открывает страницу в нужной теме —
удобно для скриншотов и записи демонстрации.

## Выгрузка отчётов

- **Markdown** формируется в браузере (`src/lib/markdown.ts`) из того же объекта отчёта,
  который показан на экране, и скачивается файлом
  `repo-health_owner_name_YYYY-MM-DD.md`.
- **PDF** — печать страницы (`Cmd/Ctrl+P` → «Сохранить как PDF»). Печатные стили в
  `src/styles/print.css` убирают навигацию, разворачивают карточки, принудительно
  возвращают светлую палитру и дописывают адреса ссылок. Текст остаётся векторным,
  кириллица не требует подключения шрифтов.
- Если бэкенд отдаёт готовые файлы (`/repos/{owner}/{name}/report.pdf`), в меню выгрузки
  появляется дополнительный пункт.

## Развёртывание

```bash
docker build -t repo-health-frontend --build-arg VITE_DATA_SOURCE=api frontend
docker run -p 8080:80 repo-health-frontend
```

`nginx.conf` отдаёт SPA с fallback на `index.html`, кеширует хешированную статику и
проксирует `/api/` на `http://backend:8000` — адрес меняется под стенд.
